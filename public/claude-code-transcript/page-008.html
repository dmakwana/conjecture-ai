The scrollbars

color-scheme was never declared. Swapping CSS variables changes what we paint, but scrollbars, form controls and the dialog backdrop are painted by the browser, and it renders them light unless the page declares which schemes it supports. Hence a dark page with bright white scrollbars.

:root { color-scheme: light dark } fixes all of them at once — the property is inherited, so it covers the modal and the CodeMirror editor too, and since the theme already follows prefers-color-scheme with no manual toggle, declaring both schemes lets the browser match automatically. Verified it's in the built CSS.

The second bug in your screenshot

Worth flagging since you didn't mention it: the SQL editor is horizontally scrolled. Every line is missing exactly its first eight characters — -- DuckD, -- Cmd/C, SELECT *. That consistent 8-character offset is what gave it away.

Cause: CodeMirror mounted inside the dialog while it was still closed, and a closed <dialog> is display: none. It measured a zero-width viewport and kept that geometry when the dialog opened. So the console was showing a truncated query on first open, which would look like the seeding was broken.

Modal now mounts its children only while open. The query text lives in SqlConsole's state above the modal and CodeMirror is controlled, so remounting the editor doesn't lose anything you've typed.

Both are single lines that read like dead code — the same trap as the margin: auto centring rule — so both are pinned by tests.
